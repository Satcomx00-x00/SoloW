## Phase 1 — Foundation (unblocks everything)

### TASK-001 — [P] Declare feature flag `ff-[feature-name]`
*File*: the project's flag registry
- [ ] Flag registered in the project's flag registry with `default: false` — the exact
      key from the spec header, verifiable by grep
- [ ] Granularity per plan §6 (must be supported by the flag system)
- [ ] Flag evaluates to `false` on a clean environment

### TASK-002 — [P] Implement validation contracts in [shared package]/schemas/[feature-name].ts
- [ ] Input schemas: `Create[Feature]Input`, `Update[Feature]Input`, `Get[Feature]Input`, `List[Feature]Input`
- [ ] Output schemas: `[Feature]Dto`, `[Feature]ListDto`
- [ ] `[Feature]ErrorCode` as `const` literal
- [ ] No `z.any()`, `z.unknown()`, `z.record(z.any())`
- [ ] Tenant key absent from all input schemas (comes from session)
- [ ] Export from barrel; typecheck passes

### TASK-003 — Implement DB schema [db package]/schema/[feature-name].ts
*Depends on*: TASK-002
- [ ] Primary key per project convention
- [ ] Tenant key column (per constitution — e.g. `organizationId`, `ownerId`) with FK
- [ ] Timestamps with timezone
- [ ] Index on `(tenant key, createdAt desc)`
- [ ] Inferred row/insert types exported

### TASK-004 — Generate and review migration
*Depends on*: TASK-003
- [ ] Migration generated by the project's ORM tooling — no handwritten SQL
- [ ] Migration reviewed line-by-line (no NOT NULL without default, no DROP without plan)
- [ ] Migration applies cleanly on a local database

### TASK-005 — [P] Add seed data
*Depends on*: TASK-004
- [ ] At least 2 tenants with non-overlapping data
- [ ] Idempotent (safe to run multiple times)
- [ ] Realistic data — no "test1", "foo"

## Phase 2 — Backend

### TASK-006 — Implement DAL [api layer]/dal/[feature-name].ts
*Depends on*: TASK-003
- [ ] `import 'server-only'` as first non-comment line
- [ ] `get[Feature]ById`, `list[Feature]s`, `create[Feature]Record`, `update[Feature]Record`, `delete[Feature]Record`
- [ ] Every read: session check → membership/ownership check → tenant-key filter in every `where`
- [ ] Tenant key required parameter on every write — never optional
- [ ] Cache keys per plan §8, TTL per plan
- [ ] Explicit column selection — no `SELECT *` / bare-table select
- [ ] Sensitive fields excluded from DTO mapper return

### TASK-007 — [P] DAL tests [test dir]/[feature-name]/dal.test.ts
*Depends on*: TASK-006
- [ ] Real database per project testing convention (ephemeral if available) — no shared mutable test DB
- [ ] Cross-tenant isolation: tenant A cannot read tenant B data
- [ ] No session → `UNAUTHORIZED`
- [ ] No membership/ownership → `FORBIDDEN`
- [ ] Cursor pagination works (page 1, advance cursor, last page)
- [ ] Test file passes with the project's test runner

### TASK-008 — [P] Implement services [api layer]/services/[feature-name].ts
*Depends on*: TASK-002
- [ ] Zero infrastructure imports (db, auth, cache, framework, headers, cookies)
- [ ] `buildCreate[Feature]Payload(input, { now })` → `Result<DBPayload>`
- [ ] `can[Feature](role, action)` → `boolean` pure authorization lookup
- [ ] `Result<T,E>` — no `throw` on business errors
- [ ] Nesting depth < 2

### TASK-009 — [P] Services tests [test dir]/[feature-name]/services.test.ts
*Depends on*: TASK-008
- [ ] 100% branch coverage
- [ ] Every `[Feature]ErrorCode` value asserted in at least one test
- [ ] Edge cases: empty string, max-length, 0, -1, Unicode, emoji
- [ ] Total runtime < 100ms
- [ ] No mocks

### TASK-010 — Implement API surface [api layer]/[routers|actions|handlers]/[feature-name].ts
*Depends on*: TASK-006, TASK-008
- [ ] Tenant-scoped entry point on every endpoint (per project convention)
- [ ] Input + output schemas imported from the shared package — never inlined
- [ ] Endpoint named for observability (span/metric name)
- [ ] Feature flag check in every endpoint
- [ ] Authorization check in every mutation
- [ ] Rate limit on writes (`rl:[feature].[action]:{userId}` or project convention)
- [ ] Wired into the app's router/exports

### TASK-011 — [P] API tests [test dir]/[feature-name]/procedures.test.ts
*Depends on*: TASK-010
- [ ] Real DB + cache per project testing convention
- [ ] No session → `UNAUTHORIZED`; no membership → `FORBIDDEN`; wrong role → `FORBIDDEN`
- [ ] Invalid input → validation error formatted to fields
- [ ] Idempotency: 2× same create → no duplicate row
- [ ] Rate limit: N+1 call → `TOO_MANY_REQUESTS`
- [ ] Cache invalidation: correct cache key absent after mutation
- [ ] Test file passes

### TASK-012 — Background job / workflow (if background work in plan §9)
*Depends on*: TASK-010
- [ ] Idempotent job/workflow processing (deterministic ID template)
- [ ] Failure captured to the project's error tracker
- [ ] Worker/workflow tests pass

## Phase 3 — Frontend

### TASK-013 — Scaffold RSC page and route segments

*Depends on*: TASK-013

- [ ] Query invalidation on mutation success
- [ ] Submit disabled while mutation is pending
- [ ] Field-level server errors surfaced on the form
- [ ] All user-facing strings via the project's i18n solution (no hardcoded literals)
- [ ] 44×44px touch targets on mobile
- [ ] Typecheck passes

### TASK-015 — [P] UI component tests
*Depends on*: TASK-014
- [ ] `Create[Feature]Form` renders; submit disabled on pending
- [ ] `[Feature]List` shows empty state when `items` is empty

## Phase 4 — E2E + Quality Gates

### TASK-016 — [P] E2E happy path [e2e dir]/[feature-name]/happy.spec.ts
*Depends on*: TASK-013, TASK-014
- [ ] Pre-authenticated storage state — no re-login per test
- [ ] Login → navigate → create → assert item visible
- [ ] Validation error path: submit invalid form → field error visible
- [ ] No `waitForTimeout` — selector-based waits only
- [ ] E2E suite passes for this feature

### TASK-017 — ⚠️ @critical E2E tenant isolation [e2e dir]/[feature-name]/isolation.spec.ts
*Depends on*: TASK-013
**MUST PASS BEFORE PR IS OPENED**
- [ ] User A on page of tenant A → data visible
- [ ] User A on URL of tenant B → 404
- [ ] User A calls API with tenant B's tenant key → 403
- [ ] User A on URL with resource ID from tenant B → 404
- [ ] Tests tagged `@critical`
- [ ] `@critical` E2E run for this feature exits 0

> For single-tenant or user-scoped projects (per constitution), replace
> tenant-vs-tenant with user-vs-user ownership isolation — the test is
> still mandatory.

  TASK-015 (UI tests) — after TASK-014
